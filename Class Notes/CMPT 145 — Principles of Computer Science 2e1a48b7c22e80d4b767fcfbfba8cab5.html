Definitions

Computers and Software

Quizlet

Main memory: where the applications and data are stored when the applications are running.

Data bus: Data gets transferred from place to place in a  computer using a system called the data bus.

CPU: The central processing unit (CPU) is where most of the computation happens. It's made up of an arithmetic logic unit (ALU) and a control unit.

ALU: The ALU knows how to do simple arithmetic operations on integers and floating point numbers, how to make comparisons to see which of the two numbers is larger, and how to perform Boolean operations like AND, OR, and NOT.

Machine cycle: All the components of a computer operate like electronic clockwork, and the CPU drives it all. The CPU performs a very simple algorithm called the machine cycle consisting of three steps:

  1. The CPU fetches an instruction, by sending a signal to main memory asking for the instruction stored at the memory address contained in the IP register. This instruction is sent along the data bus from memory and stored in the CPU's instruction register (IR). During the time that the data was travelling over the bus, the CPU updates the instruction pointer to contain the address of the next instruction.
  1. Once the instruction register contains the instruction, the CPU decodes it, which means that the CPU uses the bit-patterns in the instruction to activate the appropriate circuits in the ALU, or sometimes, in the control unit itself.
  1. When the correct circuits are ready to go, the CPU calls for the execution of the circuit: electronic signals pass through the circuit.

Machine language: A computer application (also called an executable) consists of a sequence of machine instructions, represented as binary data. Each instruction is typically very simple. For example:

  1. A load instruction retrieves data from a given address in main memory, and stores it in a given register.
  1. An add instruction adds the data in 2 given registers together, storing the result in a third register.
  1. A store instruction sends data from a given register out to a given address in main memory.

Programming language: Programming languages provide high-level abstractions like variables, loops, if-statements, and various compound data structures like lists, arrays, strings, and dictionaries.

Integrative Development Environment (IDE): An integrated development environment, or IDE, is an application that coordinates the interaction between a number of other applications, including an application that allows programmers to edit programs, and other applications like compilers, interpreters, and debuggers.

Compiler: A compiler is a computer application whose job is to take a program as input and translate it to machine

language, producing an application (also called an executable file) as output.

  1. Python does not use a compiler to create an executable.

Interpreter: An interpreter is a computer application that executes a script (that is, a text document containing instructions) one line at a time.

Assembler: An assembler is a software that converts an assembly language code to machine code.

Assembly Language: Assembly language and machine language are both low-level programming languages, but assembly language is more readable for humans. Assembly language is a symbolic representation of machine language, which is made up of binary code. ADD, MOV.

Value: A data value is any piece of information that you want to use in a script or a program.

Object: An object encodes, or represents, a data value inside a computer. Because objects represent data values, we can say that every object has a data value.

  • Examples: Booleans, None, Integers, Floats, Tuples, Strings

Heap: In the context of Python's memory management, the heap refers to the portion of memory where dynamic memory allocation takes place. It stores objects and data structures that can grow and shrink in size during program execution.

Software Design Goals & Development Process

Quizlet

Correctness: Software is correct if it does everything it is intended to do, and nothing that it isn’t supposed to do.

Efficiency: Software efficiency is a relative measure of the degree to which software consumes computational resources, including time and memory.

Robust: Software is robust if it behaves well even when things go wrong.

Adaptable: Software is adaptable if small changes in behaviour of the software can be achieved by making small changes in the software.

Reusable: Software is reusable if it can be used more than once.

Software development vs design: Software development is usually defined to include the whole life-cycle of a software system, beginning from initial intent, and concluding with deployment and maintenance. Within that cycle, there is a activity called software design, which is the process used to plan the software system.

Waterfall method: A very basic methodology is called the waterfall model. The waterfall model outlines all the activities relevant to software development, giving them a sequential order.

  1. Requirements: What the software is needed for, and what needs to be done. The result of this stage is usually a requirements document indicating what a software must do.
  1. Design: The developers come up with a plan describing how to meet the requirements. This is called the design. May not include much code, but should present a clear set of objectives and approaches for building the software.
  1. Implementation: This stage is about writing the code. Start with the low level functional units, and build upwards. Part of the implementation phase includes testing of the software. The implementation phase is complete when the design plan is completed.
  1. System testing and verification: At this stage, the application is checked, to ensure it meets the requirements.
  1. Maintenance: The application has to be delivered. Software to install the application might need to be written. Updates and upgrades need to be planned. Bug reports need to be collected, and bugs need to be fixed.

Iterative development: The iterative and incremental model of development is based on the tasks identified in the waterfall model, but is slightly more flexible. Rather than figuring out all the requirements in advance of all development, the iterative model starts with a small subset of the full requirements, and applies the waterfall model to it, repeating steps 1-4 (above), as needed.

Version control: Version control is the name for software tools that allow content providers to manage their project content and all their backups in an organized way.

Prototyping: A software prototype is an application intended to demonstrate some subset of the requirements of a software project.

Procedural Abstraction

Procedural Abstraction: When we define a function, we are creating a procedural abstraction. A function encapsulates an algorithm. A function definition separates the implementation from the function's use. Procedural abstraction allows us to look at software from two different perspectives: implementation (how we do it) and purpose (why we do it.)

Procedural abstraction and design goals:

  1. Procedural abstraction enhances reusability: a function containing encapsulated instructions can be called multiple times without copying the instructions.
  1. Procedural abstraction enhances adaptability: changes to the encapsulated code can be made often without affecting any other part of a program.
  1. This also facilitates efficiency improvements indirectly: encapsulated code can be improved, or even replaced with something much more efficient, and every call to this function benefits from the improvement.
  1. It enhances correctness: a function or procedure can be the target of focused testing: this can often be accomplished without having to test the whole program at once. It allows us to use variable names in the scope of a function without conflicting with other variables of the same name in other functions. Most importantly, once write, we can use the function by remembering its purpose, without having to keep the implementation in mind.

Procedural abstraction as part of the implementation process:

  1. One of the ways you can use procedural abstraction is to take some code that you have already written, and make it the body of a (new) function.
  1. First, making a function by encapsulating code that you’ve already written is a perfectly normal implementation activity. In fact, it is so common that many interactive development environments (IDEs, such as PyCharm) have refactoring tools that assist developers in making these kinds of changes.
  1. Second, the example emphasizes procedural abstraction as a technique for generalization; a function is more general if more of the decisions about what should happen inside the function are made outside of the function.
  1. Third, it suggests a very simple problem solving strategy: when faced with a computational problem, try to solve a very concrete instance of the problem, just by writing a script. When the script works, use procedural abstraction to make a general tool out of it.

Procedural abstraction as part of the design process: In the previous course we introduced a simple design process called stepwise or iterative refinement. Starting with a very abstract statement of the purpose of the application, the iterative refinement process keeps adding detail to abstract statements, either by adding information to a statement, or by breaking an abstract statement into a sequence of somewhat more detailed statements. Procedural abstraction can play a valuable role in this process. Each abstract statement in the iterative refinement process could be replaced by a function call to a function that has not been implemented yet.

Stepwise Refinement: Stepwise refinement, also known as incremental development or top-down design, is a problem-solving technique where you break down a complex problem into smaller, more manageable parts

Abstract Data Types

Data abstraction: Data abstraction is based on the idea that we can look at data from three different perspectives: its purpose, its operations, and the implementation of its structure.

Data Abstraction and Implementation/Design Goals: There are many benefits to hiding the details of organization and implementation. If the operations for accessing the data are correctly defined, then the data stored cannot be corrupted by using them appropriately.

  1. Furthermore, we can test an ADT and its operations very thoroughly, without having to do any system level testing of an application that uses the ADT. In other words, correctness is enhanced by abstraction.
  1. Robustness is improved, as the operations can be designed to manage unexpected situations.
  1. Adaptability is improved, as the operations can be standardized (like the operations on Python’s lists).

Data Types, in terms of values and operations: A data type consists of a set of values, and some operations on those values.

  • For example, Booleans are a data type. There are just two values in that set, and the logical operations (AND, OR, NOT) are the operations.

Data Structure, in terms of values and operations: A data structure is a data type with compound data values that are organized (or structured) in a particular way.

  • Python strings and lists are data structures: the values are compound, i.e., a collection of some kind, and there is a sequential organization imposed on the values
  • Data structures, being a special kind of data type, also have operations. You are aware of some of the list operations, at least: indexing using brackets, methods like append(), and remove(), to name a few.

Abstract Data Type: An abstract data type (ADT) is a way to describe data and the operations that can be performed on that data, without specifying how those operations will be implemented. Think of it like a blueprint for a data structure.

Linked Lists

A Linked List is object that encapsulates a single node-chain. The first node in the node-chain is called the head of the list, and the last node in the node-chain is called the tail of the list. Be careful to understand that there is exactly one chain, but we have two separate references to nodes on the chain.

  • Head: a reference to the first node in the node chain that stores the linked values. If the list is empty, this should be the Python value None. This field acts as the anchor for the linked list's node chain.
  • Tail: a reference to the last node in the node chain that stores the linked values. If the list is empty, this should be the Python value None.
  • Size: an integer representing the number of elements currently stored in the linked list. This value should be non-negative. A size of zero implies that the list has no nodes, and no data.

Algorithm Analysis

How to Use Big O notation:

  1. Identify the Input Size (n): Determine the size of the input data that the algorithm processes. This is usually represented by n.
  1. Analyze the Algorithm's Basic Operations: Break down the algorithm into its basic operations, such as loops, conditionals, and function calls. Focus on the operations that contribute significantly to the overall complexity.
  1. Determine the Number of Operations: Count the number of basic operations relative to the input size n. Consider the worst-case scenario for these operations.
  1. Identify the Dominant Term: Identify the term that grows the fastest as the input size increases. This term will dominate the overall complexity.
  1. Ignore Constants and Lower-Order Terms: In Big O notation, constants and lower-order terms are ignored because they have minimal impact on the growth rate as the input size becomes large.
  1. Express the Complexity in Big O Notation: Represent the dominant term using Big O notation, typically in the form O(f(n)), where f(n) is the function describing the growth rate.

Trees

Quizlet

Describe what a tree is, in terms of its basic organizational principles.

  • Nodes: Each element in a tree is called a node. A node contains a value or data, and it may also contain a reference (or link) to other nodes.
  • Root: The topmost node in a tree is called the root. It serves as the starting point of the tree. There is only one root in a tree.
  • Leaf Nodes: Nodes that do not have any children are called leaf nodes or leaves. They are at the "bottom" of the tree.
  • Internal Nodes: Nodes that have at least one child are called internal nodes.
  • Path: A path is a sequence of nodes connected by branches, with no repeated branches allowed.
  • Length: The length of a path is the number of branches within a path. Number of nodes is always one more than the length.
  • Edges: The connections between nodes are called edges. An edge connects a parent node to a child node.
  • Subtree: A subtree is a portion of a tree that includes a node and all its descendants. Every node in a tree can be considered the root of its own subtree.
  • Level: The level of a node is defined by its distance from the root. The root is at level 0, its direct children are at level 1, and so on.
  • Height: The height of a tree is the length of the longest path from the root to any leaf. It is the number of edges in the longest path from the root to a leaf.
  • Depth: The depth of a node is the length of the path from the root to that node. It is the number of edges from the root to the node.
  • Degree: The degree of a node is the number of children it has. The degree of a tree is the maximum degree of any node in the tree.

Explain the terms: node, child, parent, ancestor, descendant, sibling.

  • Node: A basic unit of a data structure, such as a linked list or tree, containing data and possibly links to other nodes.
  • Child: A node directly connected to another node when moving away from the root.
  • Parent: A node that has one or more nodes connected to it.
  • Ancestor: Any node connected to another node in the path from the root to that node, including the parent, grandparent, etc.
  • Descendant: Any node connected to another node in the path moving away from the root, including the children, grandchildren, etc.
  • Sibling: Nodes that share the same parent.

Describe what a binary tree is, in terms of its basic organizational principle.

  • A binary tree is a special kind of tree with no node having more than 2 children.
  • Since there are at most 2 children, we can label them left and right. Sometimes we say left sub-tree, or left node. In a diagram, we do put the left node to the left of the right node. Either or both of the subtrees could be empty.
  • A complete binary tree is a binary tree that has exactly two children for every node, except for nodes at the maximum level, where the nodes are barren

Object Oriented Programming

A mutable object has at least one public attribute that can be changed, or at least one method that changes the object's attributes.

An immutable object has no public attributes, and no methods at all that change the object's attributes.

Inheritance is a fundamental concept in object-oriented programming (OOP) that allows a class (called a child or subclass) to inherit properties and methods from another class (called a parent or superclass). This promotes code reuse and establishes a hierarchical relationship between classes.

Function overriding is a feature in object-oriented programming that allows a subclass (child class) to provide a specific implementation of a method that is already defined in its superclass (parent class).

Tasks

Search tasks: A search task is any task in which the objective is the discovery or construction of a thing (object or value) that satisfies a given set of requirements.

Decision tasks: A decision task is any task in which the objective is to determine if a set of requirements can be satisfied.

Optimization tasks: An optimization task is a task in which the objective is to find the best, according to a given set of criteria, out of all the possible things that satisfy a set of requirements.

Algorithms

Brute Force: A brute force algorithm solves a search task or an optimization task by trying every possibility.

Backtracking: A backtracking algorithm solves a search task or optimization task by organizing the exploration of possibilities using recursion.

Divide and conquer: A divide and conquer algorithm solves a task by dividing the task into independent sub-tasks. The independent sub-tasks are usually solved recursively.

Greedy: A greedy algorithm solves a search task by avoiding the exploration of all possibilities by trying to make good choices about the task based on the information that the algorithm has available at the time.

Dynamic programming: A dynamic programming algorithm is a divide and conquer algorithm combined with the technique of memoization.

1. Computers and Software

  1. Describe the different components of a computer system and how they interact
    a. Main memory: where the applications and data are stored when the applications are running. Basic memory unit is a bit, most modern computers sort than in 8-bit groups called bytes. Modern computers organize main memory as a very long sequence of bytes, where each byte has a numeric address that can be used by the computer to access the data stored in the byte very quickly. The address itself is not actually stored in memory, it is implicit in the design of the memory circuitry.
    b. Data gets transferred from place to place in a computer using a system called the data bus. In modern computers, the data bus is 8 bytes wide (64 bits), meaning 8 bytes of data can be transferred in a single action. The bus connects the main memory, the peripheral devices, and the CPU.
    c. The central processing unit (CPU) is where most of the computation happens. It's made up of an arithmetic logic unit (ALU) and a control unit.
    i. The ALU knows how to do simple arithmetic operations on integers and floating point numbers, how to make comparisons to see which of the two numbers is larger, and how to perform boolean operations like AND, OR, and NOT.
    ii. The control unit contains the circuitry for coordinating the execution of a computer program; it uses the bus to fetch data and program instructions from main memory as needed, feeds data to the ALU to perform computation, and obtains the results of such computation.
    iii. A very small amount of data can be stored right inside the CPU in extremely high-speed memories called registers. Registers can be used as temp storage for small amounts of data that will be used in the immediate future to avoid the relatively high time costs of communication with main memory.
    1) Different CPU designs have different numbers and sizes of registers, but there are some special-purpose registers that are common to all CPUs (though they may go by different names). One of these common registers is the instruction pointer (IP); also called the program counter (PC). Another is the instruction register (IR).
    iv. For most of the history of computers, a CPU had only one ALU and one control unit. In the past 15 years or so, CPUs have been built with multiple so-called "cores." Each core has a control unit, and an ALU, some registers, and a larger amount of memory called a cache. In principle, each core could be running a different application independently; in practice, some coordination between the cores is necessary, because all the cores still share the same data bus, the main memory, and all the peripherals.
    d. A peripheral device, like a disk drive or a graphics card, typically has its own control unit, some amount of memory that can only be used by its control unit, and some hardware connector to a physical device. All peripherals take direction from the computer's CPU.
  1. Describe the operational behaviour of the machine cycle
    a. All the components of a computer operate like electronic clockwork, and the CPU drives it all. The CPU performs a very simple algorithm called the machine cycle consisting of three steps:
    i. The CPU fetches an instruction, by sending a signal to main memory asking for the instruction stored at the memory address contained in the IP register. This instruction is sent along the data bus from memory and stored in the CPU's instruction register (IR). During the time that the data was travelling over the bus, the CPU updates the instruction pointer to contain the address of the next instruction.
    ii. Once the instruction register contains the instruction, the CPU decodes it, which means that the CPU uses the bit-patterns in the instruction to activate the appropriate circuits in the ALU, or sometimes, in the control unit itself.
    iii. When the correct circuits are ready to go, the CPU calls for the execution of the circuit: electronic signals pass through the circuit.
  1. Explain the difference between machine language and programming language
    a. A computer application (also called an executable) consists of a sequence of machine instructions, represented as binary data. Each instruction is typically very simple. For example:
    i. A load instruction retrieves data from a given address in main memory, and stores it in a given register.
    ii. An add instruction adds the data in 2 given registers together, storing the result in a third register.
    iii. A store instruction sends data from a given register out to a given address in main memory.
    b. Programming languages provide high-level abstractions like variables, loops, if-statements, and various compound data structures like lists, arrays, strings, and dictionaries.
  1. Explain the difference between a compiled language and an interpreted language
    a. A compiler is a computer application whose job is to take a program (that is, a text document
    containing instructions written in a programming language) as input and translate it to machine
    language, producing an application (also called an executable file) as output.
    i. Python does not use a compiler to create an executable.

4. Software Design Goals

  1. Define design goals of correctness and efficiency.

    b. Software efficiency is a relative measure of the degree to which software consumes computational resources, including time and memory.
    i. A program that is not efficient may be using an algorithm that takes more time than a better algorithm, or it may be using more memory than it needs to.   1. Define implementation goals of robustness, adaptability, and reusability.
    a. Software is robust if it behaves well even when things go wrong.
    i. Even if a program is correct, things can go wrong if the user enters bad data, or if a network connection is lost, or any other kind of external interaction behaves unexpectedly. Even if a crash is unavoidable, it would be useful for a program to do something helpful, like saving a document, or reporting that an error had occurred with a helpful error message.
    b. Software is adaptable if small changes in behaviour of the software can be achieved by making small changes in the software.
    i. The reality of writing software is that software is never truly finished. There’s just a point at which someone stops working on it. If you design your software with these kinds of possibilities in mind, making the changes will be easier.   1. Describe the difference between software development and software design.

  1. Describe the waterfall model of software development.
    a. A very basic methodology is called the waterfall model. The waterfall model outlines all the activities relevant to software development, giving them a sequential order.
    i. Requirements: What the software is needed for, and what needs to be done. The result of this stage is usually a requirements document indicating what a software must do.

25. Three Kinds of Tasks

  1. Distinguish between search tasks, decision tasks, and optimization tasks.
    1. Search tasks: A search task is any task in which the objective is the discovery or construction of a thing (object or value) that satisfies a given set of requirements.
      1. The answer can be checked, or certified, just by looking at the answer and the requirements.
      1. Examples: Calculating the square root of a number, the value we need has the requirement that if it is squared, the result if equal to the given number. Determining the solution of a set of equations involving a set of mathematical variables. The thing we need as a result if a set of numerical values, one for each variable, which makes the given equations true.
    1. Decision tasks: A decision task is any task in which the objective is to determine if a set of requirements can be satisfied.
      1. Usually phrased as a yes/no or true/false question.
      1. Examples: Does a given number have a real-valued square root? Does a set of equations involving a set of mathematical variables have a solution? Is there a time this week that everyone on the project can meet for one hour?
      1. Sometimes the answer to a decision task is to perform the related search task, and answer affirmatively if the search task has a certified answer.
    1. Optimization tasks: An optimization task is a task in which the objective is to find the best, according to a given set of criteria, out of all the possible things that satisfy a set of requirements.
      1. Examples: find the largest number in a collection. Find an itinerary for travel that has the lowest dollar cost. Find a code for text data that results in the highest compression rate of all possible codes.
      1. An optimization task is distinct from a search task in that the answer to an optimization task cannot be checked by looking at the answer and the requirements; it also requires checking that no other possible answer is better.

26. Algorithms

  1. For each of the strategies (brute-force, greedy, divide-and-conquer, recursive back-tracking , and dynamic programming), identify a practical example to which it would apply.
    1. Brute Force: A brute force algorithm solves a search task or an optimization task by trying every possibility.
      1. To design a brute force algorithm, you have to figure out what the possibilities are, and how to work through them systematically.
      1. Example: A linear search stepping through the possibilities is as simple as writing a for-loop.
    1. Backtracking: A backtracking algorithm solves a search task or optimization task by organizing the exploration of possibilities using recursion.
      1. A backtracking algorithm may be a brute force algorithm, but not always.
      1. Example: A brute force algorithm for the Maximum Tree Path search task would explore the tree using recursion, because trees are inherently recursive.
      1. Depending on the task, a backtracking algorithm might be able to avoid a very large number of possibilities by checking whether deeper recursion can possibly lead to a solution or not.
    1. Divide and conquer: A divide and conquer algorithm solves a task by dividing the task into independent sub-tasks. The independent sub-tasks are usually solved recursively.
      1. Example: The quick-sort algorithm is a divide and conquer: it separates a list into sub-lists, sorts them, and puts the pieces together.
      1. A divide and conquer approach is valuable when the computational complexity of solving the sub-tasks is much smaller than the cost of solving the whole problem.
    1. Greedy: A greedy algorithm solves a search task by avoiding the exploration of all possibilities by trying to make good choices about the task based on the information that the algorithm has available at the time.
      1. Example: The binary search algorithm is a greedy algorithm. It decides where to look for a given element of a list based on the value at the midpoint of the list.
      1. If the list is sorted, the limited information guarantees that binary search will return the correct answer. If the list is not sorted, the decision to search half of the list only will almost certainly not return the correct answer.
      1. More typically, greedy algorithms construct a solution to a search task or an optimization task piece by piece.
      1. Example: We can solve the Make Change task by deciding sequentially how many quarters to use, followed by dimes, nickels and pennies.
    1. Dynamic programming: A dynamic programming algorithm is a divide and conquer algorithm combined with the technique of memoization. This kind of algorithm is highly valuable if the divide and conquer algorithm would require re-solving of the same sub-tasks repeatedly, and the memo allows the algorithm to save time by looking up the answer instead of re-computing it.
  1. How to solve it:
    1. Try to identify the essential aspects of the problem, independent of the application. At this point, you may recognize your task as being related to a task you already know how to solve.
    1. Determine if your task is a search task, decision task, or optimization task. This will help you focus on what your algorithm needs to do.
    1. Design a brute force algorithm for your task. This will help you understand what a solution is, and can be useful for small examples.
    1. Try a divide and conquer approach.
    1. Design a dynamic programming algorithm, by simply adding a memo to your divide and conquer algorithm, if it does a lot of repeated calculations.
    1. Design a greedy algorithm that makes simple choices without trying all possibilities. This might be good enough.
    1. Design a backtracking algorithm. It might be brute force, or you might be able to save some work by cutting off fruitless possibilities before they are fully explored.
  1. Use a greedy approach to solve an appropriate problem and determine if the greedy rule chosen leads to an optimal solution.
  1. Use a divide-and-conquer algorithm to solve an appropriate problem.
  1. Use recursive backtracking to solve a problem such as navigating a maze.

Practices

  • Every function's interface documentation will cost of four parts, as follows:
    • Purpose: A brief statement of the purpose of the function, in plain language.
    • Pre-conditions: A description of every parameter for the function, including assumptions or restrictions on their values.
    • Post-conditions: A description of any effect produced by the function that could be detected after the function returns. Optionally omitted if the function has no effects.
    • Return: A description of the value returned. Optionally omitted if a function returns no value.
  • If a function has a side-effect, it is absolutely necessary that the side-effect be documented as part of the Post-conditions.
  • When applying the iterative refinement design process, define function interfaces before you define function bodies.
  • A function cannot be considered correct without proper interface documentation.
  • Write test cases for every function you write, considering test case equivalence classes and boundary cases, using white-box and black-box strategies. Test cases should be written in a test script that is separate from the function or script you are testing, and should be executable from the command-line (UNIX).
