Circuit Switching

  • In the past, calls were routed through operators who physically connected the caller and the receiver by connecting a wire to a switchboard to complete a circuit.
    • Inefficient use of bandwidth.
    • Difficult to scale.

Packet Switched Networks

  • Does not require a physical connection.
  • 1981 TCP/IP was introduced to unify disparate networks.

Birth of the Web

  • Sr Time Berners-Lee published the main features of the web we know today in 1992.
    • A Uniform Resource Locator (URL) to uniquely identify a resource on the WWW.
    • A Hypertext Transfer Protocol (HTTP) to describe how requests and responses operate.
    • A software program (web server software) that can respond to HTTP requests.
    • HTML to publish documents
    • A program (a browser) that can make HTTP requests to URLs and siaply the HTML it receives.

Web App vs Desktop

  • Advantages
    • Accessed from any internet-enabled computer
    • Used with different operating systems and browsers
    • Easier to roll out program updates
    • Centralized storage on the server, fewer security concerns about local storage.
  • Disadvantages
    • Required to have an active internet connection
    • Security concerns about sensitive private data being transmitted over the internet
    • Concerns over the storage, licensing, and use of uploaded data
    • Problems with certain websites not having an identical appearance across all browsers
    • Restrictions on software from being installed and hardware being accessed.
    • Additional plugins might interfere with JavaScript, cookies, or ads

Static to Dynamic

  • In the earliest days of the web, users could read the pages of a static website
  • Later, programs running on web servers let websites generate content dynamically. This type of website is called a dynamic server-side website

Web 2.0

  • Web 2.0 referred to an interactive experience where users could contribute and consume web content, thus creating a more user-driven web experience
  • For software developers, Web 2.0 also referred to a change in the paradigm. Programming logic, which previously existed only on the server, began to migrate more and more to the browser, which required learning JavaScript

Client-Server Model

  • Client machines are desktops, laptops, smartphones, tablets

  • Server machines host web applications, stores user and program data, and performs security authorization tasks

2 – Introduction to the WWW

Internet Protocols

  • A protocol is a set of rules that partners use when they communicate.
  • TCP/IP is an essential internet protocol.
  • These protocols have been implemented in every OS and make fast web development possible.

A Layered Architectures

  • The TCP/IP internet protocols were originally abstracted as a four--layer stack. Later subdivided into five or seven layers.
  • Link layer is the lowest layer, responsible for both the physical transmission of data across media and establishing logical links
    • It handles issues like packet creation, transmission, reception, error detection, collisions, line sharing, and more
    • One term that is sometimes used in the internet context is that of MAC (media access control) addresses
  • Internet Layer sometimes called IP layer routes packets between communication partners across networks.
    • Provides "best effort" communication. Sends message but expects no reply and provides no guarantee it will arrive in tact or at all
    • Internet uses IP addresses, which are numeric codes that uniquely identify destinations on the internet.
      • IPv4, four 8-bit integers separated by periods.
        • Port Address Translation (PAT) allows multiple, unrelated networks to make use of the same IP address.
      • IPv6 uses eight 16-bit integers and has over a billion times the numbers in IPv4.
    • Transport Layer ensures transmissions arrive in order and without error.
      • The data is broken into packets formatted according to Transmission Control Protocol (TCP).
        • Each packet has a header that includes a sequence number, so the receiver can put the original message back in order.
        • Each packet acknowledges its successful arrival back to the sender (ACK)
        • In the event of a lost packet (not ACK), packet is retransmitted
      • Sometimes we don't want a guaranteed transmission of packets. User Datagram Protocol (UDP) is used in these scenarios.
  • Application Layer protocols implement process-to-process communication.
    • HTTP: hypertext transfer protocol is used for web communication.
      • Most common type of HTTP request is the GET request when one is asking for a resource located at a specified URL to be retrieved.
      • POST request is normally used to transmit data to the server using an HTML form.
      • Response codes are integer values returned by the server as part of the response header.
      • The codes used the first digit to indicate the category of response:
        • 2## codes are for successful responses
        • 3## are for redirection-related responses
        • 4## codes are client errors
        • 5## codes are server errors
  • SSH: secure shell protocol allows remote command-line connections to servers.
  • FTP: file transfer protocol is used for transferring files between computers.
  • POP/IMAP/SMTP: email related protocols for transferring and storing email.
  • DNS: domain name system protocol used for resolving domain names to IP addresses.
    • A site can move to a different host without changing its name.
    • Generic top-level domains (gTLD) have 3 subtypes.
      • Unrestricted. TLDs include .com, .net, .org, and .info
      • Sponsored. TLDs including .gov, .mil, .edu, and others
      • As of June 2012, ICANN invited companies to launch new TLDs in order to provide more choice.
    • Country code top-level domain (ccTLD) are under the control of the countries which they represent. In the UK, businesses must register subdomains to co.uk.
  • Address resolution
    1. Client makes request for domain
    1. Client computer checks local DNS Cache
    1. If requested domain is not in the local cache, the computer requests the IP address for the domain from its primary DNS server
    1. If the primary DNS server doesn't have a record for the requested domain in its cache, it sends out the request to the Root Name Server.
    1. The Root Name Server returns the address of the relevant Top-Level Domain (TLD) server.
    1. The DNS server requests the DNS record information from the provided TLD server.
    1. The TLD name server returns with the IP addresses of the Authoritative DNS servers for the requested domains.
    1. The DNS server requests the IP address for the originally requested domain from one of the site's Authoritative DNS servers.
    1. The DNS server returns the IP address of the requested domain.
    1. The client computer can finally make its request of the domain.
  • Uniform Resource Locators (URLs) allow clients to request particular resources from the serve.r
    • URLs consist of two required components: the protocol used to connect, the domain (or IP address) to connect to.
  • A port is a type of software connection point used by the underlying TCP/IP protocol and the connecting computer. For example, port 80 is the default port for web-related HTTP requests.
    • http://funwebdev.com:8080
  • Query strings are a critical way of passing info, such as user form input, from the client to the server.
  • Fragment (URL) is used as a way of requesting a portion of a page.
  • LAMP software stack refers to:
    • Linux operating system
    • Apache web server
    • MySQL database
    • PHP scripting language

3 – HTML

HTML is a markup language. It indicates information about the content

Three main aims to HTML5:

  • Specify unambiguously how browsers should deal with invalid markup.
  • Provide an open, non-proprietary programming framework (via Javascript) for creating rich web apps.
  • Be backwards compatible with existing web.

HTML Syntax

  • Composed of content and HTML elements.
  • An HTML element is identified in the HTML do comment by tags.
  • A tag consists of the element name within angle brackets.
  • Element name appears in both the opening and closing tag.
  • HTML elements can contain attributes, which is a name-value pair that provides more information about the element.
  • An empty element does not contain text content, instead it is an instruction to the browser to do something.
    • <img>

Nesting HTML Elements

  • Often an HTML element will contain other HTML elements. In such a case, the container
  • Any elements contained within the child are said to be descendents of the parent element; likewise, any given child element may have a variety of ancestors
  • This concept is called the Document Object model (DOM) formally, though for now we will only refer to its hierarchical aspects
  • A child’s ending tag must occur before its parent’s ending tag

Semantic Markup

  • HTML documents should only focus on the structure of the document
  • Information about how the content should look is best left to CSS (Cascading Style Sheets)
  • As a consequence, beginning HTML authors are often counseled to create semantic HTML documents
  • HTML documents should not describe how to visually present content, but only describe its content’s structural semantics or meaning

Paragraphs and Divisions

  • The <p> tag is a container. It can contain HTML and other inline HTML elements
  • <div> is also a container element The<div> element has no intrinsic presentation or semantic value;
  • <hr> element is used to add a “break” between paragraphs or <div> elements.

Hyperlinks

  • Links are created using the <a> element ("anchor")
  • A link has two main parts: the destination and the label.
  • When referencing a page, the full absolute URL reference is required.
  • When referencing a resource that is on the same server, you can use relative referencing.

Information Proximity

  • Group related items together
  • The basic purpose:
    • Organize
    • If info is organized it is more likely to be read and remembered
    • Easier to use?
  • How to get it:
    • Squint your eyes and count the number of visual elements on the page by counting the number of times your eye stops
    • If there are more than 3-5, then try to regroup some of the elements
  • Avoid:
    • Too many separate elements on a page
    • Don't stick things in the corners and in the middle
    • Avoid leaving equal amounts of white space between elements unless each group is part of a subset
    • Avoid even a split second of confusion between related material
    • Don't create relationships with elements that don't belong together
    • Create intellectual relationships -> then move to visual groupings based on proximity

Alignment

  • Nothing should be placed on the page arbitrarily
  • Basic purpose: unify and organize the page
  • How to get it:
    • Be conscious of where you place elements
    • Always find something else on the page to align with, even if the two objects are physically far apart
  • Avoid:
    • Avoid using more than one text alignment
    • Break away from centered alignment unless you want a more formal (often dull) presentation

Repetition

  • Repeat some aspect of the design throughout the entire piece
  • Basic purpose: unify and add visual interest. If a piece looks interesting it is more likely to be read
  • How to get it:
    • Think of it as being consistent
    • Possibly add elements just to create repetition
    • Find existing repetition and strengthen it
    • Start to create repetitions to enhance the design and clarity
  • Avoid:
    • Avoid repetition so much that it is annoying or overwhelming
    • Be aware of contrast

Contrast

  • Basic purpose: create an interest on the page -- more likely to read, organization of info
  • How to get it:

5 – CSS 1: Selectors and Basic Styling

The rationale for CSS

  • CSS is a W3C standard for describing the appearance of HTML elements.
  • We can assign font properties, colours, sizes, borders, background images, positioning, and even animate elements on the page.
  • CSS can be added directly to any HTML element (via the style attribute), with the <head> element, or most commonly, in a separate text file that contains only CSS
  • Benefits:
    • Improved control over formatting
    • Improved site maintainability
    • Improved accessibility
    • Improved page-download speed
    • Improved output flexibility

The syntax for CSS

  • A CSS document consists of one or more style rules
  • A rule consists of a selector that identifies the HTML element or elements that will be affected, followed by a series of property:value pairs called the declaration.
  • The series of declarations is also called the declaration block.
  • Some property values are from a predefined list of keywords. Others are values such as length measurements, percentages, numbers without units, colour values, and URLs.
  • Units of measure in CSS are either:
    • relative units, in that they are based on the value of something else
    • absolute units, in that they have a real-world size
  • Some example measures:
    • px: pixel, relative measure in CSS2, absolute in CSS3 (1/96 of an inch)
    • em: Equal to the computed value of the font-size property of the element on which it is used
    • %: a measure relative to another value
    • in: inches
    • cm: centimeters

Where CSS can be located

  • CSS style rules can be located in 3 different locations
    • inline styles
      • Style rules placed within an HTML element via the style attribute.
      • Overrides any other style definitions for properties used
      • Selector is not necessary
    • embedded style sheet aka internal styles
      • Style rules are placed within the <style> element (inside the <head> element of an HTML document)
    • external style sheet
      • Style rules are placed within an external text file with the .css extension
      • When you change sheet, all HTML documents that reference it will automatically update
      • Browser can cache the external style sheet, can improve performance

The different types of CSS selectors

  • Selectors tell the browser which elements will be affected by the property values
  • Selectors allow you to select individual or multiple HTML elements.
  • The Document Object Model (DOM) is how a browser represents an HTML page internally. This DOM is akin to a tree representing the overall hierarchical structure of the document.
  • Element selectors
    • Select all instances of a given HTML element
    • You can also select all elements by using the universal element selector (*)
    • You can select a group of elements by separating the different element names with commas
  • Class selectors
    • Simultaneously target different HTML elements regardless of position in document tree
    • HTML elements labeled with the same class attribute value can be targeted for styling by using a class selector, which takes the form:
      • Period (.) followed by the class name
  • Id selectors
    • Targets a specific element by its id attribute regardless of its type or position in the doc tree.
    • Takes the form:
      • Pound/hash (#) followed by the ID name
  • Attribute selector provides a way to select HTML elements either by the present of an element attribute or by the value of an attribute
    • Helpful in styling of hyperlinks and form elements
    • Can be combined with the element id and class selectors
    • You use square brackets to create attribute selectors
  • A pseudo-element selector is a way to select something that does not exist explicitly as an element in the HTML document tree.
    • You can select the first line or first letter or any HTML element using a pseudo-element selector
  • A pseudo-class selector targets either a particular state or a variety of family relationships
    • This type of selector is for targeting link states and for adding hover styling for other elements
  • A contextual selector (also called combinators) allows you to select elements based on their ancestors, descendants, or siblings.
  • A descendant selector matches all elements that are contained within another element. The character used to indicate descendant selection is a space " "
  • A child selector matches a specified element that is a direct child of the specified element. The character used is a ">"
  • An adjacent selector matches a specified element that is the next sibling of the specified element. The character used is a "+"
  • A general selector matches All following elements that shares the same parent as the specified element. The character used is a "~"

What the CSS cascade is and how it works

  • The "Cascade" in CSS refers to how conflicting rules are handled
  • CSS uses the following cascade principles to help it deal with conflicts:
    • Inheritance
      • is the principle that many CSS properties affect their descendants as well as themselves.
      • Font, colour, list, and text properties are inheritable. Layout, sizing, border, background, and spacing properties, are not.
      • It is also possible to inherit properties that are normally not inheritable using inherit.
    • Specificity
      • is how the browser determines which style rule takes precedence when more than one style rule could be applied.
      • The more specific selector takes precedence.
      • Id selectors > class selectors > element selectors
    • Location
      • When rules have the same specificity, then the latest are give more weight.
      • Inline style > external author style sheet or an embedded style sheet

The CSS box model

  • In CSS, all HTML elements exist within an element box.

6 – Colour Theory

RGB vs CMYK

  • RGB (Red-Green-Blue) is the colour model we use in web and other digital designs. It represents colours as combinations of the colours red, green, and blue.
    • It is an additive colour system – colours are added together to create a spectrum of colour.
  • CMYK (Cyan-Magenta-Yellow-Black) is the colour model most commonly used for printing. It represents colours as combinations of the primary colours cyan, magenta, yellow, and black.
    • It is a subtractive colour model – the ink subtracts from a white (e.g., paper) background.
  • Because RGB is an additive colour model, it gives us many more options for colours – over 16.7 million.
  • In contrast, CMYK allows for just over 16,000 possibilities. Print reflects light – digital media emits it.

PRIMARY COLOURS

  • The primary colours – red, yellow, and blue – are colours that can be mixed to create new colours.
  • The secondary colours are colours that are the result of mixing two primary colours.
    • Red + yellow = orange
    • Blue + yellow = green
    • Blue + red = purple
  • The tertiary colours are colours that are the result of combining primary and secondary colours.
    • Blue (p) + green (s) = teal (t)

HUES

  • Hues are the ‘true’ colour – the dominant colour family of the particular colour that we’re examining. That is, the base colour.
    • A hue can never be black, grey, or white. It is a colour without the addition of tints, tones, and shades.
  • Tints add white to a colour to alter it. You mix a colour with white to increase the lightness of the colour.
  • Shades add black to a colour to alter it. You mix a colour with black to increase the darkness of the colour.
  • Tones - Shades add grey to a primary colour to alter it – can also be achieved by mixing tints and shades.
  • Saturation (or desaturation) alters how vivid or dull a colour is.
    • Highly saturated colours often introduce a sense of richness, energy, and vibrancy; desaturated colours are muted, calm, or neutral.

COLOUR TEMP

  • Colour temperature denotes how cool or warm a colour is. This can significantly impact how we view a design. Typically:
    • Warm colour temperature is associated with comfort, coziness, friendliness, heat, activity, and cheerfulness.
    • Cool colour temperature is associated with professionalism, distance, cold, neutrality, passivity, and cleanliness.
    • Note: this also varies by colour!

COLOUR PSYCHOLOGY

  • Colour evokes feelings and associations – and applies these associations to your design, interface, brand, or product (Mikellides, 2012). Research has found that colour can influence human response (O’Connor, 2011).
  • However, caveat emptor: many of these relationships are based on market (not empirical) research, industry wisdom, subjective interpretations, and assumptions (O’Connor, 2011).
  • Further, interpretations of colour are moderated by time and culture.
    • BLUE
      • Associated with trustworthiness (consider: the blue tick), stability, security, and calmness.
      • Adverse associations: feeling ‘blue’, coldness.
      • The most used colour on the web!
    • RED
      • Associated with passion, a call to action, power, urgency, warning, danger, and importance. May also be associated with Canada. :)
      • However – a good example of variance in cultural perceptions.
In Chinese culture, red is associated with luck, joy, and happiness.
  • GREEN
    • Associated with nature, health, wellbeing, safety, and ecofriendliness. Often used by health brands (e.g., supplements, fitness, organic foods) and outdoors brands (e.g., landscaping, hiking, agriculture).
  • YELLOW
    • Associated with energy, cheerfulness, positivity, carefreeness, optimism, and summer. Often used to appeal to children.
  • PURPLE
    • Associated with luxury and royalty (especially darker purples), magic, mystery, and grandeur.
    • Fun fact: purple was an extremely rare and expensive dye in antiquity (made from a specific species of snail).

COLOUR SCHEMES

  • In colour theory, there are colour harmonies: colours that work well together, and helped to create a well-considered and cohesive design. These are critical in employing appropriate colour schemes.
  • There are many different types of colour schemes – we’ll look at:
    • Complementary
    • Monochromatic
    • Analogous
    • Triadic

THE COLOUR WHEEL

  • This is where the colour wheel becomes important. The colour wheel allows us to understand the relationships between different colours – and which colours will, or will not, work well together.
  • Complementary colour schemes make use of contrast. In doing so, we select colours from opposite sides of the colour wheel.
  • Monochromatic colour schemes add tints and shades to the base colour.
  • Analogous colour schemes select neighboring colours to the base colour.
  • Triadic colour schemes select diametrically opposing colours at three points on the wheel.

8 – HTML Layout

What HTML tables are and how to create them

  • A table in HTML is created using the <table> element and can be used to represent info that exists in a 2-d grid.
  • Can contain any type of data
  • <table> contains any number of rows (<tr>); each row contains any number of table data cells <td>
  • Spanning rows and columns
    • All content must appear with the <td> or <th> container
    • Each row must have the same number of <td> or <th> containers
    • If you want a given cell to cover several columns or rows, then you can do so by using the colspan or rowspan attributes.

How to use CSS to style tables

  • Prior to the broad support for CSS in browsers, HTML tables were frequently used to create page layouts. Unfortunately, this practice of using tables for layout had some problems:
    • This approach tended to increase the size of the HTML document
    • The resulting markup is not semantic. Using <table> simple to get two block elements side by side is an example of using markup simply for presentation reasons.
    • Using tables for layout results in a page that is not accessible.
  • Styling tables (borders)
    • Borders can be assigned to both the <table> and the <td> element. Interestingly, borders cannot be assigned to the <tr>, <thead>, <tfoot>, and <tbody> elements.
    • Notice as well, the border-collapse property. This property selects the table's border model
      • The default is the separated model or value (each cell has its own unique borders)
      • The collapsed border model makes adjacent cells share a single border.
  • Boxes and Zebras
    • The approach is a box format, in which we simply apple background colours and borders in various ways.
  • We can then:
    • Add special styling the :hover pseudo-class of the <tr> element to highlight a row when the mouse cursor hovers over.

9 – Heuristic Evaluation

Overview the Heuristic Evaluation Process

  • Developed by Jakob Nielsen
  • Helps find usability problems in a UI design by systematic inspection
  • Small set (3-5) of evaluators examine UI
  • Independently check for compliance with usability principles ("Heuristics")
  • Different evaluators will find different problems
  • Evaluators only communicate afterwards
  • Findings are then aggregated
  • Can perform on working UI or on sketches
  • Evaluators go through UI several times
    • Inspect various elements
    • Compare with list of usability principles
    • Consider other principles/results that come to mind
  • Usability principles
    • Nielsen's "heuristics"
    • Supplementary list of category-specific heuristics
  • Use violations to redesign/fix problems
  • The evaluation has three stages:
    • Briefing session
      • The experts are told what to do. A prepared script is useful as a guide and to ensure each person receives the same briefing.
    • Evaluation period
      • Each expert typically spends 1-2 hours independently inspecting the product, using the heuristics for guidance.
      • The experts need to take at least two passes through the interface.
        • The first pass gives a feel for the flow of the interaction and the scope.
        • The second pass allows evaluator to focus on specific interface elements in the context of the whole product, and to identify potential usability problems.
      • If the evaluation if for a functioning interface, the evaluators need to have some specific user tasks in mind so that exploration is focused.
        • Suggesting tasks may be helpful but many exports do this automatically.
        • However, this approach is less easy if the evaluation is done early in design where there are only screen mock-ups or a specification; the approach needs to be adapted to the evaluation circumstances.
      • While working through the interface, specification or mockups, a second person may record the problems identified, or the evaluator may think aloud. Alternatively, they may take notes themselves. Experts should be encouraged to be as specific as possible and to record each problem clearly.
    • Debriefing session
      • The experts come together to discuss their findings and to prioritize the problems they found and suggest solutions.

Learn the Heuristics

  • H2-1: visibility of system status
    • Keep users informed about what is going on:
      • Ex. pay attention to response time:
        • 0.1s: no special indicates needed, why? perceived as instant
        • 1s: user's flow of thought stays uninterrupted but delay is noticed
        • 10s: duration if user to say focused on action
        • >10s: for longer delays, use percent-done progress bars. user will want to perform other tasks while waiting.
  • H2-2: match between system & the real world
    • Speak the user's language
    • Follow real-world conventions
  • H2-3: user control & freedom
    • Provide clearly marked exits for mistaken choices (undo, redo)
    • Don't force down fixed paths
    • Strategies:
      • Cancel button - for dialogs waiting for user input
      • Universal undo - can get back to previous state
      • Interrupt - especially for lengthy operations
      • Quit - for leaving program at any time
      • Defaults - for restoring a property sheet
  • H2-4: consistency and standards
    • Consistency of effects (predictability)
      • Same words, commands actions should always have the same effect in equivalent situations
    • Consistency of languages and graphics.
      • Same info/controls in same location on all screens/dialog boxes
    • Consistency of input
      • Require consistent syntax across complete system
  • H2-5: error prevention
    • Try to make errors impossible
      • Only allow legal data or legal commands
    • Provide reasonableness checks on input data
      • E.g. on entering order for office supplies, 5000 pencils is an unusually large order. Do you really want to order that many?
      • Did you forget to attach something?
    • Two kinds of errors.
      • Mistakes: conscious deliberations lead to an error instead of correct solution
      • Slips: unconscious behaviour gets misdirected enroute to satisfying goal. Shows up frequently in skilled behaviour, usually due to inattention. Often arises from similar actions.
    • Generic system responses for errors:
      • Gag: deals with errors by preventing user from continuing
      • Warn: warn people that an unusual situation is occurring. when overused, becomes an irritant.
      • Do nothing: illegal action just doesn't do anything. User must infer what happened.
      • Self-correct: System guesses legal action and does it instead. Can lead to a problem of trust (e.g. autocorrect)
      • Let's talk about it: System initiates dialog with user to come up with solution to problem. Compile error, google search.
      • Teach me: System asks user what the action was supposed to have meant. Action then becomes legal one.
  • H2-6: recognition rather than recall
    • Computers good at remembering things, people are not.
    • Promote recognition over recall
      • Menus, icons, choice dialog boxes vs commands, field formats
      • Relies on visibility of objects to user (but less is more)
  • H2-7: flexibility and efficiency of use
    • Experienced users perform frequent operations quickly.
    • Strategies:
      • keyboard and mouse accelerators: abbreviations, command completion, menu shortcuts, function keys, double clicking vs menu selection
      • type ahead (entering input before the system is ready for it)
      • navigation jumps. e.g., going to window/location directly, and avoiding intermediate nodes
      • history systems
  • H2-8: aesthetic and minimalist design
    • no irrelevant info
  • H2-9: help users recognize, diagnose, & recover from errors
    • Use plain language for error messages.
    • Precisely indicate the problem.
    • Constructively suggest a solution.
  • H2-10: help documentation
    • Help is not replacement for good design.
    • Simple systems: walk up and use; minimal instructions
    • Most other systems:
      • feature rich
      • simple things should be simple
      • learning path for advanced features
    • Many users do not read manuals (prefer to spend their time pursuing their task)
    • Usually used when users are in some kind of panic
      • Provide accessible documentation (online, with app for digital systems)
      • Good search/lookup tools
      • Help specific to current context
    • Sometimes used for quick reference
      • syntax of actions, possibilities
      • list of shortcuts

Phases of Heuristic Evaluation

  1. Pre-evaluation training: give evaluators needed domain knowledge & info on the scenario
  1. Evaluation: individuals evaluates UI & makes a list of problems
  1. Severity rating: determine how severe each problem is
  1. Aggregation: group meets & aggregates problems (w/ ratings)
  1. Debriefing: discuss the outcome with the design team

Perform Heuristic Evaluation

  • At least two passes for each evaluator.
  • If system is walk-up-and-use or evaluators are domain experts, no assistance needed
    • otherwise, might supply evaluators with scenarios
  • Each evaluator produces list of problems
    • explain why with reference to heuristic or other info
    • be specific & list each problem separately
  • Example problems:
    • Can't copy info from one window to another
      • violates "minimize the users' memory load" (h1-3)
      • fix: allow copying
    • Typography uses different fonts in 3 dialog boxes
      • violates "consistency and standards" (H2-4)
      • slows users down
      • probably wouldn't be found by user testing
      • fix: pick a single format for entire interface
  • Why separate listings for each violation?
    • risk of repeating problematic aspect
    • may not be possible to fix all problems
  • Where problems may be found
    • single location in UII
    • two or more locations that need to be compared
    • problem with overall structure of UI
    • something that is missing
      • common problem with paper prototypes

Severity Ratings

  • Used to allocate resources to fix problems
  • Estimates of need for more usability efforts
  • Combination of frequency, impact, persistence (one-time or repeating)
  • Should be calculated after all evals. are in
  • Should be done independently by all judges
  • Severity Rating Scale
    • 0 - don't agree that this is a usability problem
    • 1 - cosmetic problem
    • 2 - minor usability problem
    • 3 - major usability problem; important to fix
    • 4 - usability catastrophe; imperative to fix

Debriefing

  • Conduct with evaluators, observers, and development team members
  • Discuss general characteristics of UI
  • Suggest potential improvements to address major usability problems
  • Dev. team rates how hard things are to fix
  • Make it a brainstorming session, little criticism until end of session

Self-Guided vs Scenario Exploration

  • Self-guided
    • Open-ended exploration
    • Not necessarily task-directed
    • Good for exploring diverse aspects of the interface, and to follow potential pitfalls
  • Scenarios
    • Step through the interface using representative end user tasks
    • Ensures problems identified in relevant portions of the interface
    • Ensures that specific features of interest are evaluated
    • But limits the scope of the evaluation - problems can be missed

Individuals vs Teams

  • Nielsen recommends individual evaluators inspect the interface alone
    • Evaluation is not influenced by others
    • Independent and unbiased
    • Greater variability in the kinds of errors found
    • No overhead required to organize group meetings

Number of Inspectors

  • Average over six case studies shows a single evaluator found:
    • 35% of all usability problems
    • 42% of all the major problems
    • 32% of the minor problems
  • Not great, but finding some problems with one evaluator is much better than finding no problems with no evaluators.
  • Number of inspectors needed varies according to:
    • difficulty of the interface being evaluated
    • the expertise of the inspectors
  • Average problems found by:
    • Novice evaluators (no usability experience) - 22%
    • Regular specialists (Expertise in usability) - 41%
    • Double specialists (experience in both usability and the particular kind of interface being evaluated) - 60%
      • also find domain-related problems
    • Tradeoff: novices poorer evaluators but cheaper.

HE vs User Testing

  • HE is much faster
    • 1-2 hrs. per evaluator vs days-weeks
    • HE doesn't require interpreting users' actions
    • User testing is far more accurate (by def.)
      • takes into account actual users and tasks
      • HE may miss problems & find false positives
    • Good to alternate between HE & user testing
      • Find different problems, don't waste participants

Summary

  • Advantages:
    • The “minimalist” approach
    • General guidelines can correct for majority of usability problems
    • Easily remembered, easily applied with modest effort
    • Discount usability engineering
    • Cheap and fast way to inspect a system
    • Can be done by usability experts
  • Disadvantages
    • Principles must be applied intuitively and carefully
    • Can’t be treated as a simple checklist
    • Subtleties involved in their use
    • Doesn’t necessarily predict users’/customers’ overall satisfaction
    • May not have same “credibility” as user test data
  • Research results:
    • 3-5 evaluators usually able to identify 75% of usability problems
    • user testing and usability inspection have a large degree of non-overlap in the usability problems they find (i.e., it pays to do both)
  • Cost-benefit:
    • usability engineering activities often expensive / slow; but some can be quick / cheap, and still produce useful results
    • usability inspection turns less on what is “correct” than on what can be done within development constraints
    • ultimate trade-off may be between doing no usability assessment and doing some kind

Approaches to CSS layout using CSS flexbox and grid models

  • Older approaches to CSS Layout:
    • The display property in CSS provides a mechanism for the developer to change an element to block, inline, or inline-block
    • For the first 20 years of CSS, designers had to "hack" together multi-column layouts using floats and/or positioning. There may be times when you have to support legacy CSS so it makes sense to learn the basics of floats and positioning.
    • Newer approaches (flexbox and grid display modes) make columnar layouts much easier to implement
  • Floating Elements
    • It is possible to displace an element out of its position in the normal flow via the CSS float property.
    • An element can be floated to the left or floated to the right, and content is "reflowed" around the floated element.
    • A floated block-level element should have a width specified.
  • Positioning Elements
    • The position property is used to specify the type of positioning. Left, right, top, and bottom properties are used to indicate the distance the element will move.
    • absolute - The element is removed from normal flow and positioned in relation to its nearest positioned ancestor.
    • fixed - The element is fixed in a specific position in the window even when the document is scrolled.
    • relative - The element is moved relative to where it would be in the normal flow.
    • static - The element is positioned according to the normal flow. This is the default.
    • sticky - The element is positioned in according to the normal flow, and then offset relative to its nearest scrolling ancestor. This is used to allow an item to scroll, and then stay fixed in position once its scroll position is reached.
  • Overlapping and Hiding Elements
    • One of the more common design tasks with CSS is to place two elements on top of each other, or to selectively hide and display elements In such a case, relative positioning is used to create the positioning context for a subsequent absolute positioning move
  • Consider an image that is the same size as the underlying one is placed on top of the other image using absolute positioning.
  • You can hide this image using the display property.

What responsive web design is and how to construct responsive designs

  • Responsive Design
    • In a responsive design, the page "responds" to changes in the browser size that go beyond simple percentage scaling of widths
    • Smaller images will be served
    • Navigation elements will be placed as the browser window shrinks
  • Mobile First Design
    • Mobile-first design suggests that the first step in the design and implementation of a new website should be the design and development of its mobile version (rather than as an afterthought as is often the case)
    • The rationale for the mobile-first approach lies not only in the increasingly large audience whose principle technology for accessing websites is a smaller device such as a phone or tablet
    • Focusing first on the mobile platform also forces the designers and site architects to focus on the most important component of any site: the content
  • Viewports
    • The browser's viewport is the part of the browser window that displays web content
    • Mobile browsers will by default scale a web page down to fit the width of the screen
    • Generally, results in a viewing experience that works but is very difficult to read and use
  • Setting Viewports
    • The width attribute controls the size of the viewport, while initialscale sets the zoom level
  • Media Queries
    • CSS media queries are a way to apply style rules based on the medium that is displaying the file
    • Contemporary responsive sites will typically provide CSS rules for the phone displays first, then tablets, then desktop monitors; an approach called progressive enhancement
  • Scaling Images
    • Making images scale in size is straightforward, but does not change the downloaded size of the image
      • img { max-width: 100% }
    • HTML5.1 defines the new <picture> element that lets the designer specify multiple <img> elements. The browser determines which <img> to use based on the viewport size.

How to use CSS3 filters, transitions, and animations

  • CSS Effects
    • Four CSS3 modules have become broadly popular amongst designers:
      • Transformations, filters, transitions, animations
  • Transforms
    • CSS transforms provide additional ways to change the size, positions, and even the shape of HTML elements
    • CSS transforms allow you to rotate, skew, transform (move), and scale an element
    • It is also possible to transform an element in 3D space using the perspective(), rotate3d(), scale3d(), and translate3d() functions
  • Filters
    • Filters provide a way to modify how an image appears in the browser. Filters are specified by using the filter property and then one or more filter functions.
    • #someImage { filter: grayscale(100%); }
    • #anotherImage { /* multiple filters are space separated */ filter: blur(5px) hue-rotate(60deg) saturate(2); }
  • Transitions
    • Transitions are a powerful new feature of CSS3. Transitions will take effect across a length of time, provide a way to indicate that a property changes.
      • transition-delay: The delay time in seconds before the animation begins
      • transition-duration: How long in seconds for the transition to complete
      • transition-property: The name of the CSS property to which the transition is applied
      • transition-timing-function: The function that defines how the intermediate steps in the transition are calculated. CSS defines a variety of different easing functions which defines the rate of the transition.
  • Animations
    • An animation alters one or more properties between a start state and an end state (like a transition)
    • Unlike transitions, animations allow designers to control the intermediate steps through keyframe states.

    • No scoping rules
    • No modularity. Duplication. Duplication. Duplication.

11 – Affordances

Affordances

  • The perceived and actual fundamental properties of an object that determine how it could possibly be used
    • Buttons afford pressing, holes afford insertion, switches afford toggling
  • Complex things may need explaining, but simple things should not
    • When simple things need instructions, then the design has failed
  • Affordances in GUI
    • In GUIs, perception only through visuals
    • Designer creates appropriate visual affordances via familiar idioms and metaphors.

Signifiers

  • Advertising about the affordance
  • Implicit signifiers
    • Visual appearance of the object: "It looks like I can grasp it"
    • Prior knowledge or assumptions about properties: "I think it's light enough to pick up and throw"
  • Explicit signifiers
    • Deliberate instructions: "Pick up the rock to open the door"
  • Learn to read the signifiers

Constraints

  • Visible constraints
    • Limitations of the actions possible, that can be perceived from object's appearance
      • provides people with a range of usage possibilities
    • More constraints = fewer opportunities for error
      • particularly important for managing user input

Mapping

  • A UI design principle where the interface elements directly and logically relate to the physical world or the user's mental model. For example, a stove's knobs are arranged in the same pattern as the burners they control.

Feedback

  • Gulfs of execution and evaluation
  • Well-designed feedback lets the user know the state of the system, that the system has understood or responded to their actions, and what the results of their actions are.
  • Response time: Cursor lag when moving mouse across the screen

Transfer effects

  • People transfer their learning/expectations of similar objects to the current objects
    • Positive transfer: previous learning also applies to new situation
    • Negative transfer: previous learning conflicts with the new situation
  • Idioms and generic commands
    • Control X/C/V: cut, copy, paste
    • Pulldown menus
    • Scrollbars
    • Double-clicking

Population and cultural differences

  • Idioms and Population Stereotypes
    • Interface idioms are 'standard' interface features we learn, use, and remember
    • Idioms may define arbitrary behaviours
  • Idioms vary in different cultures or locations
    • Light switches: North America = down is off, Britain = down is on

Conceptual models

  • People have "mental models" of how things work, built from:
    • affordances, constraints, mapping, positive transfer, population stereotypes/cultural standards, instructions, interactions
  • Models allow people to mentally simulate operation of device
  • Models may be wrong, particularly if the attributes they are built from are misleading
  • communicate model through visual image
    • visible affordances, mappings, and constraints
    • feedback
    • cultural idioms, transfer
    • instructions augment visuals
  • all work together to remind a person of what can be done and how to do it
